# Preserve provider-native mail adapters

The shared mail domain will be implemented by provider-specific adapters behind one provider-neutral Mailbox Connection boundary rather than routing every mailbox through IMAP and SMTP. The boundary carries distinct typed Product Account, Mailbox Connection, Stable Provider Mailbox Identity, Thread, and Stable Provider Message Identity values and explicitly declares metadata synchronization, reading, provider search, push registration, sending, reply, forward, historical-categorization, and Provider Mail Action capabilities. Presentation code consumes those capabilities instead of switching on provider type. Gmail will continue using the Gmail API, generic providers will use IMAP and SMTP, Exchange Online and Microsoft 365 will use Microsoft Graph, and Exchange Web Services will be reserved for on-premises Exchange because Graph does not support it. POP3 will use a deliberately reduced legacy adapter that retrieves from one maildrop, sends through a separately configured SMTP connection authenticated as the mailbox's selected sender identity, leaves server copies by default, keeps folder and read state product-owned instead of claiming IMAP-equivalent synchronization, and has no server-side body-search capability. SMTP acceptance completes its Outbox delivery attempt and records the message in the product-owned Sent role; because POP3 cannot reconcile a provider Sent mailbox, the adapter neither claims a server copy nor retries a completed delivery solely to create one. A POP3 connection may search locally retained metadata, while body search is unavailable unless the body is already present in the bounded encrypted cache; it must not fetch or retain additional bodies solely to provide search. This accepts multiple integration implementations and explicit capability differences to retain provider-native incremental sync, push, labels, authentication, and actions instead of reducing every connection to the lowest common protocol capabilities. The EWS boundary also avoids depending on a service that [Microsoft is retiring from Exchange Online](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-ews-exchange-online).
