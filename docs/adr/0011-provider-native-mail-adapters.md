# Preserve provider-native mail adapters

The shared mail domain will be implemented by provider-specific adapters rather than routing every mailbox through IMAP and SMTP: Gmail will continue using the Gmail API, generic providers will use IMAP and SMTP, Exchange Online and Microsoft 365 will use Microsoft Graph, and Exchange Web Services will be reserved for on-premises Exchange because Graph does not support it. POP3 will use a deliberately reduced legacy adapter that retrieves from one maildrop, sends through SMTP, leaves server copies by default, and keeps folder and read state product-owned instead of claiming IMAP-equivalent synchronization. This accepts multiple integration implementations and explicit capability differences to retain provider-native incremental sync, push, labels, authentication, and actions instead of reducing every connection to the lowest common protocol capabilities. The EWS boundary also avoids depending on a service that [Microsoft is retiring from Exchange Online](https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-ews-exchange-online).
