# Accept best-effort background mail freshness

Mailbox credentials will remain device-local, so provider-native push signals may pass through the Minimal Push Metadata relay but trusted devices remain responsible for fetching and reconciling mail. Gmail and future Microsoft adapters will use provider push where available; generic IMAP will use an active connection while possible plus foreground and system-scheduled background refresh. Every authorized connection also synchronizes on app launch and foreground activation, uses a five-minute active-app fallback poll, supports manual refresh, and writes into locally observed mailbox data. Gmail recent reconciliation takes priority over Historical Metadata Backfill for the same connection: an active wake cooperatively cancels the backfill, waits for that operation to leave the per-connection gate, and only then writes recent metadata, preserving the last durable backfill checkpoint without overlapping writes. A wake that is already cancelled does not preempt useful work, queued all-connection cleanup retains its FIFO position ahead of later per-connection wakes, and a preempted backfill restores its prior freshness state instead of reporting a failure. Because Apple does not guarantee background task or silent-push execution and IMAP real-time updates require an active connection, the product accepts delayed background updates and guarantees reconciliation on the next available wake or foreground activation rather than operating a credential-holding backend mail service. See [Apple's background strategy guidance](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app), [Apple's background push guidance](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app), and [RFC 2177](https://www.rfc-editor.org/info/rfc2177/).
