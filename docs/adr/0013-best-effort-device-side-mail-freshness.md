# Accept best-effort background mail freshness

Mailbox credentials will remain device-local, so provider-native push signals may pass through the Minimal Push Metadata relay but trusted devices remain responsible for fetching and reconciling mail. Gmail and future Microsoft adapters will use provider push where available; generic IMAP will use an active connection while possible plus foreground and system-scheduled background refresh. Every authorized connection also synchronizes on app launch and foreground activation, uses a five-minute active-app fallback poll, supports manual refresh, and writes into locally observed mailbox data. Gmail recent reconciliation takes priority over Historical Metadata Backfill for the same connection: an active, current wake cooperatively cancels the backfill, waits for that operation to leave the per-connection gate, and only then writes recent metadata, preserving the last durable backfill checkpoint without overlapping writes. The preemption request remains visible while it waits so a backfill that has just become the lock owner cannot miss cancellation. A wake that is already cancelled or whose persistence fence is already stale does not preempt useful work, its provisional status does not supersede an untouched backfill completion but prevents cancellation or failure from restoring an older visible status, beginning preemption advances the completion fence so a successful backfill cannot overwrite the active push status, cancellation is checked again after gate ownership and after a backfill page returns, queued all-connection cleanup retains its FIFO position ahead of later per-connection wakes, and a backfill completion changes freshness state only when no newer superseding external sync status has been recorded. Because Apple does not guarantee background task or silent-push execution and IMAP real-time updates require an active connection, the product accepts delayed background updates and guarantees reconciliation on the next available wake or foreground activation rather than operating a credential-holding backend mail service. See [Apple's background strategy guidance](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app), [Apple's background push guidance](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app), and [RFC 2177](https://www.rfc-editor.org/info/rfc2177/).
