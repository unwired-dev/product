# Accept best-effort background mail freshness

Mailbox credentials remain device-local, so provider-native push signals may pass through the Minimal Push Metadata relay but trusted devices remain responsible for fetching and reconciling mail. Gmail uses provider push where available; a generic IMAP connection whose verified capabilities include `IDLE` keeps an active Inbox IDLE session, synchronizes after each change signal, and reconnects after interrupted sessions. Connections without `IDLE` rely on foreground and system-scheduled refresh. Every authorized connection also synchronizes on app launch and foreground activation, uses a five-minute active-app fallback poll, supports manual refresh, and writes into locally observed mailbox data. Because Apple does not guarantee background task or silent-push execution and IMAP real-time updates require an active connection, the product accepts delayed background updates and guarantees reconciliation on the next available wake or foreground activation rather than operating a credential-holding backend mail service. See [Apple's background strategy guidance](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app), [Apple's background push guidance](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app), and [RFC 2177](https://www.rfc-editor.org/info/rfc2177/).
