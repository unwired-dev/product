# Queue provider mail actions optimistically

Provider Mail Actions will update local mailbox presentation immediately and persist as ordered Pending Provider Actions scoped to their Mailbox Connection until the provider confirms them. Pending actions retry after connectivity returns; permanent rejection restores provider-derived state and surfaces a visible failure, while product-owned actions such as Pin synchronize independently. Bulk selections may span connections but expose only their shared capabilities, execute per-connection batches, preserve successful batches, and report failures by connection rather than pretending to provide a cross-provider transaction. This accepts reconciliation complexity to keep locally cached mail responsive and usable offline without silently losing user intent.
