# Queue provider mail actions optimistically

Provider Mail Actions will update local mailbox presentation immediately and persist as ordered Pending Provider Actions scoped to their Mailbox Connection until the provider confirms them. Each action has a stable idempotency key and immutable attempt record. Pending actions retry after connectivity returns; an ambiguous response is reconciled with the provider before retrying, and an IMAP move, archive, or copy is retried only after reconciliation proves the source-to-target mapping. If that mapping cannot be proved, the action stops for user resolution rather than replaying an unreconciled mutation. Permanent rejection restores provider-derived state, then replays later pending actions in order so newer optimistic changes are preserved, and surfaces a visible failure. Product-owned actions such as Pin synchronize independently. Bulk selections may span connections but expose only their shared capabilities, execute per-connection batches, preserve successful batches, and report failures by connection rather than pretending to provide a cross-provider transaction. This accepts reconciliation complexity to keep locally cached mail responsive and usable offline without silently losing user intent.
