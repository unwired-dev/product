# Queue provider mail actions optimistically

Provider Mail Actions will update local mailbox presentation immediately and persist as ordered Pending Provider Actions scoped to their Mailbox Connection until the provider confirms them. Each action has a stable idempotency key and immutable attempt record. One action executes at a time per connection; transient failures retry with bounded exponential backoff and jitter for at most five attempts, then stop in a visible user-action-required state while preserving the unresolved optimistic state for reconciliation or discard. While an action is user-action-required, later actions for that connection remain queued; reconciliation or discard resolves the blocked action, restores provider-derived state when needed, and replays those later actions in order. Other connections continue independently. An ambiguous response is reconciled with the provider before retrying, and an IMAP move, archive, or copy is retried only after reconciliation proves the source-to-target mapping. If that mapping cannot be proved, the action stops for user resolution rather than replaying an unreconciled mutation. Permanent rejection restores provider-derived state, then replays later pending actions in order so newer optimistic changes are preserved, and surfaces a visible failure. Product-owned actions such as Pin synchronize independently. A bulk batch expands into ordered actions queued behind existing work for each Mailbox Connection; it is serialized within that connection, while batches for different connections may proceed independently, preserve successful batches, and report failures by connection rather than pretending to provide a cross-provider transaction. This accepts reconciliation complexity to keep locally cached mail responsive and usable offline without silently losing user intent.
