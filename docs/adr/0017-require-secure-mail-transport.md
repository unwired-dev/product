# Require secure mail transport

IMAP, SMTP, and POP3 connections will require TLS 1.2 or newer with valid server identity before authentication. The client will prefer implicit TLS and permit STARTTLS only when it is successfully negotiated before credentials are sent; it rejects authentication before TLS is established and certificate failures, and provides no invalid-certificate override. Exchange Web Services uses HTTPS with TLS 1.2 or newer and valid server identity rather than implicit TLS or STARTTLS. Device-side setup may use DNS email-service discovery defined by [RFC 6186](https://www.rfc-editor.org/rfc/rfc6186.html) or a bundled reviewed provider catalog, but the user reviews discovered endpoints and may configure them manually; discovery never uploads addresses or server settings to the product backend. The reviewed non-secret connection definition may synchronize only through end-to-end encrypted Product Sync, while credentials remain device-local. This deliberately sacrifices compatibility with obsolete or misconfigured servers to protect mailbox credentials and content, following [RFC 8314](https://www.rfc-editor.org/rfc/rfc8314.html).
