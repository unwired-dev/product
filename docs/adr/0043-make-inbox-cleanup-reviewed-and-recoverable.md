# Make Inbox Cleanup reviewed and recoverable

Inbox Cleanup will detect candidates on device and present a reviewable proposal rather than deleting mail automatically. The first-release eligibility predicate is the **Inbox Cleanup Candidate** definition in `CONTEXT.md`: a message must currently belong to Inbox, be read, be assigned the **Newsletters & Promotions** **System Category**, be older than 90 days, not belong to a **Pinned Thread**, and have no reply evidence; the stated category and Spam or Trash exclusions also apply. A proposal selects individual candidates, may select a whole Thread only when every current message satisfies that same predicate, and requires a final action that states how many messages will move to the Mail Provider's Trash; permanent erasure is outside this feature.

The Apple client owns detection, review, final revalidation, and enqueueing through the existing durable Provider Mail Action boundary. A Unified Inbox proposal may span Mailbox Connections and reports each connection's outcome without claiming a cross-provider transaction. Immediately before enqueueing, the client revalidates every selected candidate against the same eligibility predicate. If the eligible set changes, it returns to confirmation, identifies skipped messages, and displays the updated final Move to Trash count; only that reconfirmed set is enqueued. One proposal contains at most 500 messages, explains each group in plain language, and permits deselection; successful moves offer immediate Undo when supported, while provider Trash remains the longer recovery boundary. The TypeScript backend receives neither candidate content nor provider execution requests.

The card appears only when one sender has at least ten eligible messages or the selected Inbox has at least fifty candidates. Not Now records, through End-to-End Encrypted Product Sync, a 30-day cooldown for the same Product Account and selected Inbox scope: either one Mailbox Connection's Inbox or the Unified Inbox selection. Its baseline is the total eligible candidate count in that scope at dismissal. The card may return early when the current eligible count for the same scope reaches at least twice that baseline. When the cooldown expires or the doubled-count card is shown, the baseline is cleared; a later Not Now records a new dismissal time and baseline. The first release keeps these thresholds fixed and exposes enablement and suppression settings rather than speculative rule tuning.
