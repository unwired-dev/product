# Classification engine interface

Future Learning Signals are independently keyed and merged for each normalized sender and Category. A new positive or negative signal for Orders therefore cannot replace the current signal for Newsletters & Promotions from the same sender.

When concurrent User Overrides add and remove the same membership, the associated Future Learning Signal follows the same causal remove-wins result; devices resolve the membership and sender-and-Category signal together before publishing either outcome.

The Apple client will place email categorization behind a local Classification Engine interface rather than binding product logic directly to one Apple on-device AI API. Apple on-device AI is the preferred implementation, but the interface allows rule-based, platform-version-specific, or local model fallbacks while preserving the same output contract and keeping category immutability outside the classifier.

The first implementation is a deterministic local rule-based engine. Provider metadata sync sends available subject, snippet, and selected headers as Minimized Classification Input. The engine explicitly requests body text when metadata is insufficient; only then may the categorization service read an existing entry from the **Bounded Encrypted Body Cache**. Categorization never fetches a missing body from any provider, and classification or learning-signal load failures leave the message in Uncategorized State. Historical messages bypass the engine unless the user explicitly selects a bounded date range, using received timestamps for received messages and sent timestamps for sent messages, and already categorized messages always bypass it.

Assigned Message Category memberships are encrypted on device and written to Product Sync using an opaque payload identifier derived from the Mailbox Connection and Stable Provider Message Identity. A synced membership set is loaded before local classification so another trusted device's existing membership remains immutable. The typed Product Sync record-family boundary owns bounded exact-read batching and concurrency, key access, associated-data binding, encryption, conditional writes, and retry limits for these records. The categorization domain continues to derive the compatible opaque identifier, validate the complete decoded Stable Provider Message Identity, apply the Category Conflict Rule, and map sustained contention to its domain error.

A batch membership read omits an individual record that fails decryption, decoding, or identifier binding while returning the remaining valid records. A single-record read stays strict and surfaces the failure. Consequently, a corrupt membership leaves its message in Uncategorized State during a batch read instead of failing categorization for the entire batch; every returned record still passes identifier binding and identity validation.

A user may add or remove any Message Category membership, including on Uncategorized historical mail. The encrypted membership records each Category's User Override state and, for received messages only, carries a Future Learning Signal derived from the message's From address; sent-message overrides never create a Future Learning Signal. The signal uses the later of the user-action time and the overridden message's provider timestamp as its lower bound, while a separate unclamped user-action timestamp orders repeated overrides for both the message and its sender. Trusted devices may use that signal when categorizing Uncategorized messages received later from the same sender, but System Categorization never applies it to messages received before the override or to messages that already have that Category. The newest override for each sender and Category is stored in its own bounded encrypted payload, addressed by a keyed sender-and-Category digest. Clients derive digests only for senders and Categories in the current eligible message batch and fetch those exact payloads in bounded requests, so they neither expose sender addresses, scan unrelated sender signals or per-message memberships, nor grow one unbounded index document. Clients update both per-message memberships and sender signals with optimistic version checks and bounded retries against newer ciphertext, preserving unrelated concurrent sender-and-Category updates and the newest membership for an overlapping sender and Category while surfacing sustained contention as a typed sync error. Reapplying the same Category membership preserves its original learning-signal lower bound regardless of trusted-device write order; changing membership establishes a new lower bound. User Override state and learning data remain inside end-to-end encrypted payloads; the backend continues to store only opaque ciphertext and identifiers.

The Category Conflict Rule is enforced on trusted devices after decrypting competing membership sets. Atomic create-if-absent writes keep the first System Categorization for the same Category when devices classify the same message before sync converges. A User Override replaces a System Categorization for that Category regardless of arrival order. Concurrent changes to different Categories merge. When a conditional write reveals competing User Overrides for the same Category, concurrent removal wins over addition; otherwise every device converges on the first stored user action instead of falling back to last-write-wins. A later user action that begins after observing the prior override can still replace it and is ordered by its user-action timestamp. The backend participates only through opaque conditional writes and cannot inspect assignment sources, timestamps, or categories.
