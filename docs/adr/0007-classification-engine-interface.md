# Classification engine interface

The Apple client will place email categorization behind a local Classification Engine interface rather than binding product logic directly to one Apple on-device AI API. Apple on-device AI is the preferred implementation, but the interface allows rule-based, platform-version-specific, or local model fallbacks while preserving the same output contract and keeping category immutability outside the classifier.

The first implementation is a deterministic local rule-based engine. Gmail metadata sync sends subject, snippet, and selected headers as Minimized Classification Input. The engine explicitly requests body text when metadata is insufficient; only then may the categorization service read an existing entry from the encrypted On-Demand Body Cache. Categorization never fetches a missing body from Gmail, and classification or learning-signal load failures leave the message in Uncategorized State. Historical and already categorized messages bypass the engine.

Assigned Message Categories are encrypted on device and written to Product Sync using an opaque payload identifier derived from Stable Provider Message Identity. A synced assignment is loaded before local classification so another trusted device's existing assignment remains immutable.

A user may replace any Message Category, including Uncategorized historical mail. The encrypted assignment records that the category is a User Override and carries a Future Learning Signal derived from the message's From address. The signal uses the later of the user-action time and the overridden message's provider timestamp as its lower bound, while a separate unclamped user-action timestamp orders repeated overrides. Trusted devices may use that signal when categorizing Uncategorized messages received later from the same sender, but System Categorization never applies it to messages received before the override or to messages that already have a category. The newest override for each sender is stored in its own bounded encrypted payload, addressed by a keyed sender digest. Clients derive digests only for senders in the current eligible message batch and fetch those exact payloads in bounded requests, so they neither expose sender addresses, scan unrelated sender signals or per-message assignments, nor grow one unbounded index document. Clients update both per-message overrides and sender signals with optimistic version checks and bounded retries against newer ciphertext, preserving unrelated concurrent sender updates and the newest assignment for an overlapping sender while surfacing sustained contention as a typed sync error. Reapplying the same category preserves its original learning-signal lower bound regardless of trusted-device write order; changing category establishes a new lower bound. User Override state and learning data remain inside end-to-end encrypted payloads; the backend continues to store only opaque ciphertext and identifiers.
