# Model Outbox delivery as immutable attempts

Offline and transiently failed Outbox messages will retry automatically with bounded exponential backoff, while authentication, policy, invalid-recipient, and other permanent failures stop for user action. Retries stop after 10 total attempts, including the initial delivery attempt, or seven days after the first delivery attempt, whichever comes first, and move the Outbox message to a terminal user-action state that records the last failure; an explicit user retry creates a new immutable attempt without changing the failed attempt. Every attempt has a stable idempotency key and immutable attempt record. After an ambiguous provider response, the client first reconciles delivery status with the provider using that key or the message identifier before retrying; it does not submit a duplicate delivery while the outcome remains unknown. SMTP transactions with an ambiguous response after DATA are not retried automatically because SMTP cannot provide this reconciliation guarantee; they require explicit user resolution. An atomic compare-and-swap claim serializes editing, cancellation, and provider handoff: an edit or cancellation that claims the pending attempt first prevents its dispatch, while a successful handoff claim makes that attempt immutable and requires edits or cancellation to wait for its terminal state. Editing an eligible message then creates a new immutable Outgoing Delivery Attempt instead of mutating an attempt already in flight. Actionable and failed attempts remain durable; the Apple app removes sent, cancelled, and superseded attempts in the same atomic write that records the terminal state, then returns the removed attempt to the caller in memory, except when a cancelled or superseded attempt still owns a provider draft requiring deletion. The Apple app owns that deferred cleanup and retains the attempt until provider-draft deletion completes. Product Account teardown in the Apple app owns account-wide Outbox cleanup and performs it before credentials or encryption keys are cleared. This accepts explicit delivery state and bounded attempt history to prevent ambiguous retries and accidental duplicate sends without retaining terminal message content indefinitely.

Each attempt also persists the provider-handoff deadline selected from the synchronized Undo Send preference when that attempt is created. Turning Undo Send off makes the attempt immediately eligible for provider handoff; 10-, 20-, and 30-second selections remain cancellable until their durable deadline, including across app restarts. Later preference changes affect only new or edited attempts. Attempts written before this field existed retain the legacy 10-second fallback.

Sign-out blocks and drains composer sends before account-wide Outbox cleanup. Account switching suspends old-account delivery tasks and completes Outbox cleanup before removing mailbox credentials; a cleanup failure restores the prior Product Account so its credentials remain available for provider-draft deletion.

Microsoft Graph Outbox attempts persist the immutable provider draft identifier after draft creation. Retryable delivery reuses the same draft through the attempt's stable extended-property identity. Editing, cancellation, permanent abandonment, Mailbox Connection removal, and Product Account cleanup delete the provider draft before discarding the local attempt or authorization; a deletion failure leaves the delivery outcome unchanged, retains encrypted device-local cleanup state, and retries without treating the message as ambiguously delivered. A missing provider draft is already clean because it may have been sent or removed independently.
