# Model Outbox delivery as immutable attempts

Offline and transiently failed Outbox messages will retry automatically with bounded exponential backoff, while authentication, policy, invalid-recipient, and other permanent failures stop for user action. Every attempt has a stable idempotency key and immutable attempt record. After an ambiguous provider response, the client first reconciles delivery status with the provider using that key or the message identifier before retrying; it does not submit a duplicate delivery while the outcome remains unknown. Pending and failed messages remain editable or cancellable until an attempt is handed to the provider; an in-flight attempt must reach a terminal state first. Editing then creates a new immutable Outgoing Delivery Attempt instead of mutating an attempt already in flight. This accepts explicit delivery state and attempt history to prevent ambiguous retries and accidental duplicate sends.
