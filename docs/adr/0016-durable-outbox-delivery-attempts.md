# Model Outbox delivery as immutable attempts

Offline and transiently failed Outbox messages will retry automatically with bounded exponential backoff, while authentication, policy, invalid-recipient, and other permanent failures stop for user action. Retries stop after 10 total attempts, including the initial delivery attempt, or seven days after the first delivery attempt, whichever comes first, and move the Outbox message to a terminal user-action state that records the last failure; an explicit user retry creates a new immutable attempt without changing the failed attempt. Every attempt has a stable idempotency key and immutable attempt record. After an ambiguous provider response, the client first reconciles delivery status with the provider using that key or the message identifier before retrying; it does not submit a duplicate delivery while the outcome remains unknown. SMTP transactions with an ambiguous response after DATA are not retried automatically because SMTP cannot provide this reconciliation guarantee; they require explicit user resolution. An atomic compare-and-swap claim serializes editing, cancellation, and provider handoff: an edit or cancellation that claims the pending attempt first prevents its dispatch, while a successful handoff claim makes that attempt immutable and requires edits or cancellation to wait for its terminal state. Editing an eligible message then creates a new immutable Outgoing Delivery Attempt instead of mutating an attempt already in flight. Actionable and failed attempts remain durable; sent, cancelled, and superseded attempts are removed atomically after their result is returned to the caller. Product Account teardown owns account-wide Outbox cleanup and performs it before credentials or encryption keys are cleared. This accepts explicit delivery state and bounded attempt history to prevent ambiguous retries and accidental duplicate sends without retaining terminal message content indefinitely.
