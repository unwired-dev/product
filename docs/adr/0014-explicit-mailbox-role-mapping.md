# Require trustworthy mailbox role mapping

Unified Mailboxes will normalize provider mailboxes and labels through canonical Mailbox Roles. Provider-native semantics and IMAP `SPECIAL-USE` markers are trusted when unambiguous; otherwise connection setup asks the user to map required roles and permits later changes. A changed mapping reclassifies existing local metadata and applies to future synchronization; the prior mapping remains available until migration completes and is restored if migration fails. Every pending Provider Mail Action whose target or meaning changes is cancelled until the user reconfirms it against the new mapping. The product accepts additional setup friction and will not guess from localized folder names, avoiding incorrect sent-mail placement and destructive actions against the wrong folder. See [RFC 6154](https://www.rfc-editor.org/rfc/rfc6154.html).

Generic IMAP setup therefore reads `SPECIAL-USE`, accepts a role only when exactly one provider mailbox declares it, and asks for explicit Drafts, Sent, Archive, Spam, or Trash values only where the result is missing or ambiguous. Saved setup can be reopened and reverified after changing those mappings. The setup screen does not infer localized names. A Legacy POP3 Connection omits server mailbox mappings because its reduced contract uses product-owned local roles.
