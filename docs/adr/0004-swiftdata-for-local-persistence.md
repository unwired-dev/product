# SwiftData for local persistence

The Apple client will use SwiftData first for local persistence because the product should stay Apple-native and define models in Swift code rather than writing SQL schemas. This favors developer speed, SwiftUI integration, and minimal external dependencies, while accepting that advanced migrations, encryption strategy, sync-engine internals, and cache behavior may need careful validation as the mailbox model grows.

Gmail Durable Message Metadata is represented by connection-scoped SwiftData records containing the locally encoded metadata value, never a message body. A separate connection-scoped checkpoint records the current full-scan generation and next Gmail page token. The newest 50 provider-visible messages establish Initial Mailbox Availability; subsequent pages are committed independently so cancellation, network loss, Low Power Mode, or process restart can resume without discarding usable metadata. A full scan marks prior records as reconciliation candidates, clears that marker as each provider-visible message is observed, and deletes the remaining candidates only with the final page. This preserves newly observed concurrent mail and prevents partial scans from turning unfinished pagination into deletion. Legacy file-backed Gmail metadata migrates on first scoped load and is removed only after the SwiftData save succeeds.
