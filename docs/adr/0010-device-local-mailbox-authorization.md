# Keep mailbox authorization device-local

Product Sync synchronizes the non-secret definition of each Mailbox Connection and the Default Sending Connection, but provider passwords, app passwords, OAuth refresh tokens, and equivalent credentials remain in the current trusted device's Keychain. A device that receives a definition without local credentials presents authorization-required state and exposes no provider-reading, push, action, or sending capabilities. It retains a synchronized Default Sending Connection even when that connection is unavailable locally and requires authorization or explicit sender selection instead of substituting another identity.

Mailbox Authorization prefers OAuth for known providers and may use passwords or app-specific passwords only over Secure Mail Transport; client-certificate and enterprise SSO authentication are deferred. Every device must obtain its own authorization, accepting additional setup friction to prevent provider credentials from entering backend or cross-device sync and to preserve the existing device-held credential boundary.

The generic-mail verification boundary applies this decision entirely on device. It supports XOAUTH2 access tokens, app-specific passwords, and passwords, saves the reviewed connection definition and credential together in a ThisDeviceOnly Keychain item scoped to the Product Account, and clears those items on sign-out or account switch. The final session-validity check and Keychain save are serialized with Product Account cleanup for that account, so cleanup cannot be followed by a late credential write. After successful verification, the reviewed non-secret address, username, endpoints, transport modes, authorization method, and role mappings synchronize separately through encrypted Product Sync; the credential remains only in the local authorization payload. Because these protocols do not supply a shared immutable account identifier, the stable mailbox identity uses the exact username that successfully authenticated to the verified endpoints after trimming surrounding whitespace, without case folding; the reviewed address remains display metadata rather than the authenticated identity.

Remove Device Authorization clears only the current device's provider credentials, cached mail, metadata, and push state while preserving the encrypted connection definition. Gmail removal, including removal tombstones observed from another device, serializes with on-demand and prefetched body loads plus push renewal so cleanup runs after any already-started cache or push-state write. Remove Mailbox Connection Everywhere first completes the initiating device's local cleanup, then replaces the synchronized definition with a durable encrypted tombstone and clears it as the default sender without choosing a replacement. Other devices reconcile that tombstone before provider access, clear their local authorization, and never delete provider mail. If initiating-device cleanup or tombstone publication fails, the definition remains visible so the user can retry safely.

Each encrypted Mailbox Connection definition and each device-local Mailbox Authorization carry a monotonically increasing authorization generation. Removal advances the generation and retains that history even after the same stable provider identity is explicitly recreated; the historical tombstone is hidden from the active connection view but remains inside encrypted Product Sync and signals current clients to purge local state unless they already hold authorization for the recreated generation. Each device durably records the generation of a completed local purge so a retained tombstone does not repeatedly clear already-absent credentials, while any stale credential that reappears still forces cleanup. The generation floor is also retained in a separate encrypted ledger that older app versions do not rewrite, preventing a legacy definition save from downgrading the fence; advancing an uncommitted write preserves the prior committed floor until the matching Product Sync write commits. A provider adapter advertises authorization and performs provider access only when the local credential generation matches the active synchronized definition. Gmail loads synchronized removal and generation history before it verifies or registers statusless scoped or legacy credentials; credentials without generation evidence may migrate only when that history contains no later fence for their identity. EWS setup performs Product Sync reads and compare-and-swap writes outside the connection gate, then saves the device-local authorization through a revision-checked gate commit so an intervening cleanup, removal, re-add, or competing setup invalidates stale work. Legacy definitions and credentials decode as generation zero, while legacy removal tombstones decode as generation one, so existing authorized connections remain usable and a pre-removal credential cannot be blessed by a later re-add.
