# Sync mail workflow preferences, not device state

Mail-handling choices should follow the user across trusted devices, while choices constrained by one device should remain local. Inbox behavior, read-state rules, swipe assignments, compose behavior, signatures, templates, category configuration, global notification and category-eligibility settings, per-connection notification policies, and account-wide and per-connection read-receipt policies therefore use End-to-End Encrypted Product Sync. Appearance, operating-system notification permission and presentation, generic notification fallback, remote-content and download behavior, storage controls, diagnostics, and settings-navigation state remain device-local. Provider credentials continue to live only in each device's Keychain. This boundary preserves a consistent mail workflow without making hardware, operating-system permissions, network exposure, storage use, or secrets behave as portable account data.

Mail Workflow Preferences for Inbox presentation use the versioned `mail-workflow-preferences:inbox` singleton. The trusted device persists its effective values and pending field edits locally, while only encrypted payloads cross Product Sync. Thread-list density, preview length, contact images, Category badges, and attachment indicators are synchronized. The current Mail View and selected mailbox are device-local; every new session starts in Unified Inbox with Important selected.

Reading behavior and Read Receipt policy use the separate versioned `mail-workflow-preferences:reading` singleton. It synchronizes message-open timing, optional mark-read behavior after replying or archive/delete, account-wide incoming and outgoing Read Receipt defaults, and sparse per-Mailbox Connection receipt overrides. Provider capabilities remain device-observed connection state rather than synchronized preference data; unsupported receipt controls stay visible and disabled instead of silently substituting another policy.

Swipe assignments use the versioned `mail-workflow-preferences:swipes` singleton. Leading and trailing edges each retain an ordered list of at most two actions, and the full-swipe choice is synchronized with them. A trusted device resolves each configured action against the affected message's current state and Mailbox Connection capabilities; unsupported actions are omitted without changing the meaning of the remaining assignments.
