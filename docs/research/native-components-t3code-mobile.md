# Native components, motion and swipe-back: Unwired Mail and T3 Code

Research date: 2026-10-19. Scope: maintained Expo `apps/mobile`, with a short Mac comparison. This is a source investigation, not a visual review or an implementation proposal approved for delivery.

## Conclusion

Both applications render native views. T3 Code delegates more **whole interactions** to platform controls: navigation bars, toolbar items, integrated search, native form sheets, wheel/date pickers and an iOS segmented control. Unwired Mail combines native split navigation, system context menus, Liquid Glass and system file/photo/share presenters with more application-built React Native chrome and panels. T3 Code still uses ordinary React Native components extensively; its iOS button is a `Pressable`, not a SwiftUI `Button`. [Unwired design bridge][u-design-native], [Unwired controls][u-controls], [T3 header][t-header], [T3 picker][t-number], [T3 button][t-button].

The most relevant difference for swipe-back is navigation ownership. Unwired Mail selects a reader with `router.replace` and explicitly shows a split column; T3 Code maintains React Navigation history and reconciles native stack/split dismissals back into that history. Installing Reanimated or changing a back-button icon does not resolve this distinction. [Unwired shell][u-shell], [T3 card adapter][t-stack], [T3 workspace adapter][t-workspace].

T3 Code's implementation also carries a substantial compatibility cost: it uses a **vendored screens v5 fork and custom iOS navigator adapters**, rather than a stock Expo Router configuration. Treat its behavior as a reference to evaluate, not a dependency swap to copy. [T3 dependencies][t-package], [T3 adapter][t-stack], [embedded fork provenance in the pinned tarball][t-tarball].

## Animations

### Unwired Mail

Observed `useMenuMotion` uses RN `Animated.timing` with `useNativeDriver: true`: menu entry 200 ms, grow-panel entry 300 ms, exit 150 ms. A menu scales from 0.95; a grow panel scales from 0.3. Reduce Motion is read initially and subscribed to dynamically: transforms are removed and grow entry becomes 200 ms, while opacity transitions remain. It starts conservatively with reduced motion enabled. These are concrete animation choices, not evidence of poor performance. RN's native driver sends supported animation work to native before playback, so it is incorrect to describe these menus as necessarily running every frame on JavaScript. [Motion implementation][u-motion], [Animated native driver][d-animated].

Reanimated is used for the Filters popover's `FadeIn.reduceMotion(ReduceMotion.System)`. The compact Filter presentation instead requests RN Modal's `fade`; the source does not apply the same explicit Reduce Motion setting to that Modal fade. This warrants runtime checking, not an assertion that the operating system ignores accessibility settings. Main composer presentation is a conditional overlay in the root shell; there is no explicit interactive pan or entry/exit animation there. [Filter motion][u-filters], [composer overlay][u-composer-overlay].

### T3 Code

Observed Reanimated use is broader and tied to actual interaction: shared workspace pane timing is 260 ms with cubic in/out and `ReduceMotion.System`; pull-request rows use 180 ms layout, 140 ms entry and 100 ms exit; row actions use `ReanimatedSwipeable`, an explicit spring, and worklet-driven dismissal (220 ms translation/fade, then 180 ms collapse). [Pane timing][t-pane-motion], [PR motion][t-pr-motion], [row motion][t-row-motion].

Navigation and native control motion are separately owned by UIKit/screens or the native control. For example, `UISegmentedControl` selection echoes are explicitly guarded to avoid restarting UIKit's settling animation. The generic segmented-control file's 160 ms Reanimated slide is **not** the iOS implementation because `.ios.tsx` supplies the native control. [Native segment][t-segment], [platform wrapper][t-segment-wrapper], [generic segment][t-segment-generic].

Accessibility handling is deliberate in inspected paths: Reanimated effects commonly request system Reduce Motion; the work-log shimmer additionally listens for changes and stops when reduced motion is enabled, the app is inactive or the screen loses focus. Its internal `ReduceMotion.Never` is guarded by that outer condition, rather than evidence that it ignores the preference. This sample does not establish universal accessibility compliance. [Shimmer lifecycle][t-shimmer], [Reanimated accessibility semantics][d-reduced-motion].

## Swipe-back: exact paths and remaining uncertainty

### Unwired Mail

1. **Inbox → reader:** `selectMessage` calls `router.replace('/message/[id]')` and `show('secondary')`; the effect follows `detail` to show secondary or supplementary. Inbox's custom Back calls `show('primary')`. This is a split-column journey, not a conventional pushed Expo Router stack with accumulated message history. [Shell selection and column changes][u-shell].
2. **Compact settings/privacy:** `SettingsCover`, `PrivacyAccess`, and Error Reporting details mount a second `ScreenStackItem` with `gestureEnabled` and reconcile `onDismissed` into application state. These paths explicitly opt into screens' native dismiss gesture. Source does not specify full-screen response distance or a custom interactive transition. [Settings cover][u-settings-cover], [privacy access][u-privacy-access], [settings detail][u-settings].
3. **Composer:** a full-screen or floating RN overlay sits outside the split screens. Closing runs the editor's finish/save path and changes the route; the root overlay does not define swipe-to-dismiss. It should not be assumed to inherit the reader's stack gesture. [Composer overlay][u-composer-overlay].
4. **Chrome:** `UnwiredNavigationChrome` hides/restores the nearest navigation bar; it does not itself configure an interactive-pop recognizer. A hidden native bar plus an application Back control is not proof that a swipe is disabled or enabled. [Native chrome][u-design-native].
5. **Other gestures:** the header's downward responder opens the Command Palette. Exhaustive source search of `apps/mobile/app` and `apps/mobile/src` found no `Swipeable`, `GestureDetector`, `PanResponder` or `Gesture.Pan` implementation at this revision. The current message row instead wraps its press target in a native context menu and exposes accessibility actions. Do not confuse the existing downward palette gesture, or legacy Swift swipe settings, with implemented mail-row swipe actions or verified reader swipe-back. [Message row][u-row], [palette responder][u-palette].

**Framework interpretation:** the native split container can own compact navigation behavior, but this report does not establish exactly which horizontal start regions succeed in the deployed screen hierarchy. Installed dependency names and `show()` calls cannot prove the result. The present source also has no shown root callback that converts a native column-back gesture into a different reader URL. Test whether the selected route and visible column remain coherent after a completed or cancelled swipe and after reopening the same message.

### T3 Code

1. **iOS card stacks:** `V5CardStackView` renders native `Stack.Screen`s. It maps `gestureEnabled === false` and React Navigation removal guards into `preventNativeDismiss`. Native events drive React Navigation pops; outgoing routes/descriptors remain available until UIKit finishes, preventing premature unmounts and duplicate pops. [Adapter lifecycle][t-stack].
2. **Compact and expanded workspace:** workspace screens use native split columns and nested stacks. `Split.Screen.onDismiss` checks `isNativeDismiss` and dispatches a calculated pop. Column changes are explicit, with split `presentsWithGesture`; appearance/disappearance events are forwarded for transition listeners. [Workspace implementation][t-workspace].
3. **Recognizer implementation:** the vendored native controller wraps UIKit's edge `interactivePopGestureRecognizer` and, on iOS 26+, `interactiveContentPopGestureRecognizer`; it defers to the original delegates and blocks protected route removal. Beginning either pop cancels RN surface touches, including if the transition later cancels, so the underlying row/button is not also activated. This is stronger evidence than generic native-stack defaults; it still does not prove that every screen accepts a content-area swipe. [Pinned native controller][f-pop].
4. **State races:** Home thread selection detects an outgoing native swipe-back route and pushes a fresh Thread key if a new selection arrives before dismissal finishes; otherwise the delayed dismissal could discard it. [Selection-race handling][t-selection].
5. **Intentional gesture exceptions:** New Task on iOS disables its parent dismiss gesture while the keyboard is visible and restores it on cleanup. Form sheets propagate removal prevention, while individual routes may set `gestureEnabled: false`. "Swipe-back everywhere" is therefore not the source contract. [Keyboard gate][t-keyboard], [sheet guard][t-sheet], [route configuration][t-routes].
6. **Row swipes are separate:** `ReanimatedSwipeable` exposes trailing row actions, spring behavior, trackpad support, vertical failure bounds and scroll gating. A vertical movement over 4 points suppresses row swiping; drag end delays re-enabling 160 ms unless momentum events take over. These controls arbitrate row swipes versus vertical scrolling; they do not by themselves prove compatibility with native pop gestures or horizontal code/diff scrolling. [Row gesture configuration][t-row-gesture], [scroll gate][t-scroll-gate].

The official native-stack guide describes native platform navigation and its options, but T3's iOS adapter does not forward every native-stack option directly to a stock `NativeStackView`. For example, the observed card path uses `gestureEnabled` as a dismissal guard rather than passing a generic `fullScreenGestureEnabled` prop. Read the adapter and fork before applying current documentation defaults. [Native-stack guide][d-stack], [custom adapter][t-stack].

## Practical priorities

These are recommendations derived from the source comparison, not approved scope changes.

1. **Verify the existing back contract first.** On iPhone and compact iPad, exercise Mailboxes → Inbox → reader; complete and cancel edge/content swipes; reopen the same row; repeat with search, a keyboard, a sheet and composer open. Assert visible column, selected URL/parameters, saved Draft state and absence of accidental row activation. Add targeted native interaction coverage for those results. Existing native Inbox tests explicitly check that the compact custom header has no navigation bar; this does not cover swipe-back. [Existing header test][u-native-test], [shell contract][u-shell].
2. **Evaluate native headers/search/sheets one interaction at a time.** A native integrated search bar or form sheet is a more meaningful adoption target than wholesale replacement of every RN view. Compare required controls, detents, cancellation, keyboard handling, accessibility and current Figma behavior first. T3 demonstrates an approach, but its screens fork and SDK58 APIs need a separate compatibility evaluation against Unwired's SDK57/screens4 stack. [Version catalogs][u-catalog], [T3 versions][t-package], [T3 native header][t-header], [T3 sheets][t-sheet].
3. **Preserve native-driver motion that already works.** The likely gap is coverage of interactive transitions and interruption/cancellation, not a blanket need to replace `Animated` with Reanimated. Standardize motion/accessibility decisions for custom overlays and verify the Filter Modal fade under Reduce Motion. Prefer Reanimated when a gesture must continuously drive animation/layout, as in T3 row swipes. [Unwired motion][u-motion], [Filter presentation][u-filters], [T3 row worklet][t-row-motion].
4. **Require runtime evidence before claiming parity.** Check physical iPhone/iPad, compact/regular resizing, hardware keyboard/trackpad, VoiceOver, Reduce Motion toggled while open, nested scroll views and WebView editor selection. Report completed/cancelled transitions and touch cancellation separately from animation smoothness. No such runtime evidence was collected here.
